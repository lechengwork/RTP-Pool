雙池收斂架構 · 池 ① 細節

安全網池

盯每個(總代×遊戲×版本)遊戲本身的自然 RTP,只在被推到「明顯不對」時才反應。它不是把 RTP 拉回目標的主力——那是記債池——它是一張抓粗異常的網。

搭配「雙池收斂架構 v2」　·　數值待校準　·　ε 採主動介入(見第 8 節)

1它的角色

先講清楚它不是什麼:它不負責把客戶需求造成的偏移修回來(那是記債池的事),也不做 1% 級的微調。

它負責的是抓遊戲本身「明顯不對」的粗偏移:

  • 某款遊戲的 RTP 設定 / 版本掛錯
  • 被濫用、外掛、或非預期的玩法造成 RTP 大幅偏離
  • 任何記債池不知道、但遊戲自然結果已經歪掉的狀況
為什麼它可以「很鬆、很少動」

7 天 8,500 萬筆資料顯示:遊戲數學自己就把大池收在 96.9~97.2%(目標 97%)。所以正常情況根本不需要它出手——它只是一張網,平常不作用,出事才接住。

2量什麼

用精確恆等式,量它負責的那些轉的 RTP:

安全網的 D/B D/B = r − (Σwin / Σbet) = 目標RTP − 實際RTP
關鍵:干涉轉不進安全網

安全網只記正常轉和它自己收斂的轉(用該轉最終的 win);客戶需求、還款這些干涉轉不進安全網,只進記債池。兩本帳把所有轉分乾淨、不重疊,就不會重複算。(這條在 Phase 2 記債池上線後才用到——細節到記債池文件再講。)

3欄位與參數

每個池子(key = 總代×遊戲×版本)存的東西分兩類:每轉會變的動態欄位,和有全域預設值的參數。r 從版本現算(0970→0.970),不用存。

名稱類型意義值從哪來
B動態累積總押注(EWMA)每轉更新
D動態Σ(bet·r − win)(EWMA)每轉更新
spinCount動態累積轉數(判斷暖身)每轉 +1
last_seen動態最後 spin 時間(死池清理)每轉更新
λ參數記憶長度(轉)全域預設
ε參數 ★粗偏移門檻全域預設,可 per 池覆寫
暖身門檻參數累積幾轉才作用全域預設
K參數候選數(主動介入才用)全域預設
★ ε 可以 per 池覆寫

四個參數都有一組全域預設值(所有池子共用)。其中 ε 可以針對個別池子(總代×遊戲×版本)單獨覆寫預設;λ、暖身門檻、K 一律用全域值。

ε 可覆寫正好用來處理少數大獎型遊戲——它們自然噪音大(±20~44%),在全域 ε 下會狂觸發;給它們一個較鬆的 ε覆寫即可,其餘 100 多款照全域預設走,不用一款一款配。

4衰減:跟「轉數」走,不跟時間

每一轉把舊值打折 λ 再加本轉(win = 該轉最終結果):

B ← λ·B + bet　　D ← λ·D + (bet·r − win)

記憶長度 ≈ 1/(1−λ) 轉。選轉數而非時間,是因為這是統計性保證——信心來自累積了幾個結果,不是過了多久。用轉數,池子玩快玩慢行為一致、有效樣本固定。(要出手時怎麼挑結果,見第 7 節。)

5死池清理

轉數衰減有個副作用:沒人玩就不衰減,舊 D/B 會凍住。所以:

  • 閒置滿 30 天 → 砍掉池子(對齊月對帳週期)。實作(TTL 自動過期 or 掃描刪除)交給工程。
  • 月對帳只讀、不重置活池——滾動的池子本來就讓每個月都貼目標,對帳自然過;月初歸零反而讓每個池子重暖身。
因為是硬懸崖,要知道

轉數衰減閒置時是凍結的,所以 30 天是硬切:資料在第 30 天前全權重、之後整個清掉。閒置快 30 天的池子若來散客,會照舊 D 出手直到重新暖身——有界、可接受。

6啟用門檻(暖身)

剛開(或剛被清)的池子只玩過幾轉,D/B 是純噪音,不能出手。累積到暖身門檻才啟用:

if spinCount < 暖身門檻:  只記帳,不出手
else:                    正常判斷(見下節)
用「轉數」當門檻,不用 B(押注額)

因為一個大戶的錢會把 B 灌爆、卻只是 +1 轉。轉數對大戶和小玩家一視同仁,比較不會被騙著提早解暖身。暖身過就 latch 住(死池由 30 天閘處理)。

(先前討論過用「有效樣本 n_eff」更嚴謹,但因為安全網走鬆 ε、又不是 RTP 主控,簡化用轉數即可;n_eff 留到日後真需要細偵測再說。)

7觸發與收斂(完整每一轉流程)

派工用一個合併條件就夠:「暖身中 或 在容許範圍內」→ 正常轉;否則收斂。

# 找到這筆 spin 的池子 (總代,遊戲,版本);  r = 版本/1000

if now − last_seen > 30 天:  砍掉池子重來        # 死池清理
last_seen = now

if spinCount < 暖身門檻  or  |D/B| < ε:
    最終結果 = 正常 Spin(要 1 個)
else:
    最終結果 = N 個候選中「|D| 最小」的那一個     # 要 N 個(零副作用);只有這個算數

# 結算
B ← λ·B + bet
D ← λ·D + (bet·r − win)
spinCount += 1
  • 只有最終回傳的那 1 個結果算數——進帳、進 Jackpot、進報表;其餘 N−1 個候選完全丟棄。
  • 走到這裡的轉,不論正常或收斂都要更新 B、D、spinCount(用該轉最終 win)。
  • 在完整的雙池派工裡,安全網是最後一道:先看客戶需求(借)、再看有沒有債要還(θ 門檻),都沒有才輪到它。這份是 Phase 1 的安全網視角,所以只有它自己。
  • 重要:借與還那兩種干涉轉完全不進安全網——不更新 B、不更新 D、不累加 spinCount,只進記債池。安全網要量的是遊戲數學自己,把我們做過手腳的轉餵進去,它就會去追自己造成的偏移。完整派工見「2_雙池收斂架構」§5。

怎麼挑?——挑最接近 win* 的候選

「挑 |D| 最小」具體怎麼做:目標是讓結算後的 D 盡量接近 0(D=0 就是 RTP 剛好在目標)。把更新式 D_新 = λ·D + (bet·r − win) 設成 0、解出 win,就是「最理想的 win」:

收斂目標 win*令 D_新 = 0：  0 = λ·D + bet·r − win
→  win* = λ·D + r·bet

但只能從 N 個真實候選裡挑,所以挑最接近 win* 的那個——它讓 D 最接近 0(這就是「|D| 最小」)。而且 B 這轉固定 +bet、對所有候選一樣,所以「|D| 最小」也等於「|D/B| 最小」。方向自動雙向修:

目前 D意義win* vs r·bet挑
D > 0欠玩家、RTP 偏低偏高高 win 追回
D < 0多給了、RTP 偏高偏低低 win 修回

例:bet=10, r=0.97, λ=0.99, D=200 → win* = 0.99×200 + 0.97×10 = 207.7;候選 [0, 5, 150, 300] 挑最接近的 150 → 結算後 D = 0.99×200 + (9.7−150) = 57.7,往 0 靠近了。

8ε:主動介入,而且一定要鬆

安全網採主動介入——|D/B| > ε 就挑結果(要 N 個候選、挑最接近 win* 的)把 RTP 拉回。ε 是出手的門檻,不是任何通知或人工流程的門檻。

ε 一定要「鬆」——資料證明的

老虎機的自然 RTP 因鯨魚/jackpot 會晃 ±10~40%。ε 設太緊,會一直對噪音出手。實測 ε=2% 單池:

記憶 M觸發率Math 負載(K=10)
5 萬61%6.5×
20 萬45%5.0×
100 萬32%3.9×

所以安全網的 ε 建議 ~10%(粗調),絕不是 2%。要修 1% 級的東西是記債池的事,不是安全網。

主動介入 → 大獎型遊戲一定要用 ε 覆寫

主動模式下,誤觸發 = 真的介入(挑結果 + Math 負載 + 動到玩家)。全域 ε=10% 時,大獎型遊戲會被過度介入(遊戲 2004 可到 82% 的轉)。所以那幾款務必用 per 池覆寫給較鬆的 ε(見第 3 節),否則 Math 負載和玩家干涉會被它們拉爆。

為什麼主動介入,而不是記下來就算了

遊戲數學本來就收在目標,所以安全網平常很少動;但一旦遊戲真的歪掉(設定錯/濫用),偏移會持續累積下去,只記帳不出手等於任由它漂。主動介入是當下就把玩家看到的 RTP 拉回,收斂在同一轉內完成。代價是誤觸發時會動到玩家——用鬆 ε + 大獎型覆寫把它壓到最低。

9校準(定全域預設值)

四個參數的全域預設值怎麼定:

參數建議起點怎麼定
λ長記憶(~20 萬轉起)校準窗看自然 D/B 抖動 vs 記憶
ε~10%(粗調,鬆)設在多數遊戲的自然抖動之上
暖身門檻~2~5 萬轉抖動收斂到 ε 要幾轉
K5~10沿用現有

校準方法:拿歷史逐轉資料(每列一筆 spin:總代、遊戲、版本、押注、贏分、時間),掃一組 λ 回放,量各池自然 |D/B| 的抖動 → 設全域 λ、ε;看抖動收斂到 ε 要幾轉 → 設暖身門檻。定門檻只需歷史結果即可。

大獎型遊戲用覆寫處理,不改全域

校準時會看到少數大獎型遊戲在全域 ε 下誤觸發過高(實測全域 ε=10% 時,40 款裡約 20 款 >5%,最凶的達 82%)。作法是把那幾款用 per 池覆寫給較鬆的 ε,全域預設維持不動。

10為什麼這樣

決定理由
衰減跟轉數不跟時間統計信心來自「幾個結果」,轉數記憶讓行為與流量無關;死池用 30 天閘另解
門檻用轉數不用 B大戶的錢會灌爆 B、卻只是 +1 轉;轉數比較不被騙
ε 鬆(~10%)、全域預設可覆寫緊 ε 在鯨魚噪音下觸發率 32~61%、Math 3~6 倍、砍正當贏分;安全網只抓粗偏移。大獎型遊戲用 per 池覆寫給較鬆 ε
ε 走主動介入遊戲歪掉時當下把玩家 RTP 拉回,而不是只記帳任它漂;高波動遊戲用 per 池覆寫較鬆 ε 避免過度介入
干涉轉不記安全網只記正常轉+自己收斂轉,與記債池不重疊、不重複算(Phase 2 才用到)
